# Дизайни

*[English](DESIGNS.md)*

Вигляд меню живе окремо від програми: кольори, тло, годинники, шрифти й вигляд кожного віджета.
Дизайн — це **один файл**: поклади його в теку, і він з'явиться в *Налаштування → Вигляд* із
живим попереднім переглядом.

- **Вбудовані дизайни** лежать у `designs/`, і оновлення їх замінюють.
- **Свої** живуть на хості в `/etc/pve-homelab/designs/<вид>/`. Оновлення цю теку не чіпають, а
  файл там із тим самим id, що й вбудований дизайн, замінює його.
- Адміністратор може поставити їх і з меню: *Налаштування → Вигляд → Мої дизайни → Встановити
  дизайни…* приймає один чи кілька файлів `.css` / `.js` або `.zip` із кількома (у теках за видом,
  як-от `themes/…`, або просто файлами з `@kind` у кожному).

| Вид | Файл | Що це |
|---|---|---|
| Тема | `themes/<id>.css` | кольори й шрифт заголовків як CSS-змінні |
| Тло | `backgrounds/<id>.css` | що позаду екрана входу й панелі |
| Годинник | `clocks/<id>.js` | як намальовано час (невеликий ES-модуль) |
| Шрифт | `fonts/<id>.css` | вебшрифт, який можна вибрати для інтерфейсу чи годинника |
| Вигляд віджета | `widgets/<id>.css` | як виглядає віджет `<id>`; його логіка — це віджет, вбудований або [свій](#свої-віджети) |

Id — це ім'я файла: малі латинські літери, цифри, `-` і `_`.

## Як працювати над дизайном

```bash
./demo.sh                                              # демо з живим оновленням
python3 tools/new_design.py theme neon-night           # копія вбудованого дизайну під новим id
# редагуй .demo/state/designs/themes/neon-night.css і зберігай:
# відкрите демо змінюється одразу, без перезавантаження
open "http://127.0.0.1:8900/?seat=igpu&showcase=themes:neon-night"
```

- **`tools/new_design.py <вид> <id>`** бере за основу вбудований дизайн (`--from` вибирає який),
  ставить новий id усюди, де дизайн його використовує, і пише заголовок з `@kind` та назвами
  (`--name`, `--name-uk`). Пише в теку дизайнів демо, якщо `--to` не каже іншого.
- **Своя тека дизайнів**, скажімо git-репозиторій: `./demo.sh --designs ~/my-designs` і
  `new_design.py … --to ~/my-designs`. На хості скопіюй файли в `/etc/pve-homelab/designs/` або
  встанови їх із меню.
- **Живе оновлення** в демо ввімкнене. Збережений файл підміняє свій стиль чи годинник на місці;
  коли дизайн додано чи видалено, сторінка перезавантажується. На хості воно вимкнене, поки в
  `config.yaml` немає `designer: true`.
- **Вітрина** `?showcase=<вид>:<id>` (themes, backgrounds, clocks, fonts) показує один дизайн у
  всіх станах одразу: день, дощ, гроза, вечір, ніч, сніг і панель удень та вночі. Тему видно на
  кількох тлах; тло, годинник чи шрифт — у кількох темах. Esc закриває. Вигляд віджета видно на
  панелі, якщо додати туди сам віджет.

## Заголовок

Кожен дизайн починається з коментаря, **по одному `@ключу` на рядок**:

```css
/*
 * @kind theme
 * @name.en Neon night
 * @name.uk Неонова ніч
 * @desc.en cold, electric
 * @order 20
 */
```

| Ключ | Що означає |
|---|---|
| `@kind` | `theme`, `background`, `clock`, `font` або `widget`. Потрібен, коли файл приходить сам по собі (не в теці виду); `new_design.py` пише його завжди |
| `@name.<мова>` | назва в налаштуваннях для кожної мови (просто `@name` — англійська) |
| `@desc.<мова>` | короткий опис під назвою |
| `@order` | місце в списку, менше — вище (вбудовані займають 10–160) |
| `@group` | тло: `scape` (пейзаж: рушій додає сонце, місяць, зорі, хмари, туман, погоду) або `flat` |
| `@tod` | тло: завжди ця пора доби (`night`, `dawn`, `day`, `dusk`) |
| `@family` | шрифти: значення CSS font-family, напр. `"Onest", sans-serif` |

## Тема

CSS-змінні на селекторі теми; усе інше виводиться з них. Тема може й перемальовувати віджети чи
[переставляти частини меню](#як-переставляти-частини), якщо **кожне її правило лишається під її власним
`[data-skin="<id>"]`**: усі теми вантажаться одночасно, а сторінка вибирає одну, тож правило без нього
змінило б і всі інші теми. Таку тему інсталятор не прийме.

```css
.A[data-skin="neon-night"],.A [data-skin="neon-night"]{
  --acc:#00e5ff;            /* акцент: кнопки, виділення, відтінок неба */
  --acc2:#ff3df0;           /* другий акцент: сяйво неба, градієнти */
  --acc-ink:#001418;        /* текст на тлі акценту */
  --acc-text:#7ff3ff;       /* текст кольору акценту на темному */
  --acc-soft:rgba(0,229,255,.14);   /* підфарбовані тла */
  --acc-line:rgba(0,229,255,.7);    /* рамки кольору акценту */
  --glass:rgba(16,22,31,.62);       /* панелі */
  --solid:radial-gradient(80em 50em at 80% 120%,#2a0b3a,#05070f 60%);  /* тло «тема» */
  --display:"Onest",system-ui,sans-serif;   /* годинник і заголовки, якщо людина не вибрала шрифт */
  --lf:saturate(1);         /* фільтр на вбудований SVG-пейзаж */
}
```

## Тло

Малюй `.bgx[data-k="<id>"]`, а для пейзажу ще й шари всередині, від дальнього до ближнього:
`.stars .sun .cl .cl2 .l1 .l2 .l3 .l4 .fg .wx`. Сам малюєш `.bgx` і ті з `.l1`–`.l4`, які
потрібні; з `@group scape` сонце чи місяць, зорі, хмари, туман і погоду рушій домалює сам.

Бери палітру, яка вже йде за темою й порою доби:
`--sky1 --sky2 --sky3` (від верху до обрію), `--far --mid --ink` (пагорби від дальніх до ближніх).

На момент реагуй через атрибути `.bgx`:

- `data-tod`: `night`, `dawn`, `day`, `dusk`
- `data-wx`: `clear`, `partly`, `overcast`, `rain`, `thunder`, `snow`, `fog`

```css
.bgx[data-k="my-hills"]{background:linear-gradient(180deg,var(--sky1),var(--sky2) 50%,var(--sky3))}
.bgx[data-k="my-hills"] .l1{left:0;right:0;top:55%;bottom:0;background:var(--mid);
  clip-path:polygon(0 40%,30% 10%,60% 35%,100% 15%,100% 100%,0 100%)}
.bgx[data-k="my-hills"][data-wx="snow"] .l1{background:linear-gradient(180deg,#eef3f8 0 15%,var(--mid) 40%)}
```

Добрі приклади: `designs/backgrounds/mountains.css` (пейзаж), `gradient.css` (пласке).

## Годинник

ES-модуль із двома експортами. `render` викликається щосекунди й має чіпати лише те, що
змінилося.

```js
export const css = `
  [data-clockk="big"]{font-size:1.2em;letter-spacing:.05em}
`;                                   // діє лише на цей годинник через [data-clockk="<id>"]

export function render(el, t) {      // t = {h, m, s, text: "HH:MM", date: Date}
  if (el.textContent !== t.text) el.textContent = t.text;
}
```

Добрі приклади: `designs/clocks/digital.js` (найпростіший), `flip.js`, `analog.js`.

## Шрифт

```css
/*
 * @kind font
 * @name My font
 * @family "My Font", sans-serif
 */
@import url("https://fonts.googleapis.com/css2?family=My+Font:wght@400;600;800&display=swap");
```

Він вантажиться лише тоді, коли хтось його вибирає чи відкриває його попередній перегляд.

## Вигляд віджета

Стилі для `.A .w[data-w="<id>"]`, де `<id>` — id віджета. Класи всередині віджет вибирає сам;
найшвидше почати з копії вбудованого вигляду:
`python3 tools/new_design.py widget host`.

## Як переставляти частини

Тема може не лише фарбувати, а й переставляти екрани: форму входу ліворуч, верхній рядок униз, як
статусний рядок термінала, бічну колонку праворуч. Чіпляйся лише за ці частини. Їхні назви й те, що
в них, оновлення не міняють (місце в розмітці може змінитися); будь-який інший клас меню — його
внутрішня справа і може змінитися без попередження.

| Гачок | Екран | Що в ньому |
|---|---|---|
| `[data-scr="saver"]`, `[data-scr="login"]`, `[data-scr="dash"]` | | самі екрани |
| `[data-part="saver-time"]`, `[data-part="saver-weather"]` | заставка | годинник і дата; погода |
| `[data-part="login-intro"]` | вхід | рядок хоста, заголовок, годинник, дата й віджети |
| `[data-part="login-widgets"]` | вхід | колонка віджетів (усередині `login-intro`) |
| `[data-part="login-form"]` | вхід | хто входить, пароль |
| `[data-part="login-about"]`, `[data-part="login-power"]` | вхід | рядок версії; мова й кнопка заставки |
| `[data-part="topbar"]` | панель | верхній рядок: `brand`, `open-tabs`, `topbar-tools` |
| `[data-part="dash-body"]` | панель | усе під рядком: `sidecol` і `dash-main` |
| `[data-part="sidecol"]` | панель | бічна колонка віджетів |
| `[data-part="dash-main"]` | панель | `systems` і `services` |
| `[data-part="systems"]`, `[data-part="services"]` | панель | ряд систем; вкладки вебсервісів і гостей |

```css
/* верхній рядок унизу, форма входу ліворуч */
@media (min-width: 901px) {
  .A[data-skin="tmux"] [data-part="topbar"]{position:absolute;left:0;right:0;bottom:0;border-top:1px solid var(--edge);border-bottom:0}
  .A[data-skin="tmux"] [data-part="dash-body"]{top:0;bottom:3.6em}
  .A[data-skin="tmux"] [data-scr="login"]{grid-template-columns:28em 1fr}
  .A[data-skin="tmux"] [data-part="login-form"]{order:-1}
}
```

- **Тримай це в `@media (min-width: 901px)`.** До 900 px меню має власне розташування в одну колонку
  для телефонів і планшетів вертикально.
- **Скоуп — сторінка, `.A[data-skin="<id>"]`** (без пробілу перед дужкою), тоді мініатюри в
  «Налаштування → Вигляд» лишаються як є.
- **Клавіатура:** стрілки йдуть за тим, що на екрані, тож рушать слідом; Tab іде за розміткою, і
  коли частини переїжджають далеко, він стрибає. Перевір обидва у вітрині й демо.

## Свої віджети

Віджет — це частина з логікою: що він читає і що показує. Вбудовані лежать у
`web/widgets/<id>/widget.js`; твої — на хості в `/etc/pve-homelab/widgets/<id>/widget.js`,
оновлення їх не чіпають, і вони з'являються в *Налаштування → Панель* (чи *Екран входу*) поруч із
вбудованими. Id не може збігатися з id вбудованого віджета. Його вигляд — такий самий дизайн, як
інші: `widgets/<id>.css`.

```bash
./demo.sh
python3 tools/new_widget.py uptime            # .demo/state/widgets/uptime/: widget.js, i18n/en.json,
                                              # i18n/uk.json і вигляд у designs/widgets/uptime.css
# додай «Uptime» у Налаштування → Панель і редагуй: збереження віджета чи його рядків
# перезавантажує сторінку, збереження вигляду перемальовує його на місці
python3 tools/new_widget.py uptime --to ~/my-widgets   # тека з тією ж будовою, що й /etc/pve-homelab
./demo.sh --widgets ~/my-widgets/widgets --designs ~/my-widgets/designs
```

Новий віджет — робочий приклад кожної частини контракту: читає `/api/host`, має опцію й рядки
англійською та українською.

```
widgets/uptime/
  widget.js          код
  i18n/en.json       його рядки, по файлу на мову
  i18n/uk.json
```

```js
export default {
  zones: ['side', 'login'],          // куди його можна ставити
  public: true,                      // дозволений на екрані входу (читає лише публічні дані)
  source: '/api/host', every: 10,    // що читає (GET з API меню або (ctx) => Promise) і як часто (с)
  options: [                         // форма ⚙ з живим переглядом у Налаштуваннях; label — ключ його рядків
    { key: 'load', type: 'toggle', label: 'opt_load', default: true },
  ],                                 // toggle · select · checks · number · text · date · list · textarea
  render: (data, { t, ui, opts }) => `<h4>${ui.esc(t('title'))}</h4>…`,   // повертає HTML
  after: (el, data, ctx) => {},      // необов'язково: підключити обробники до намальованого
};
```

```json
{
  "title": "Аптайм",
  "opt_load": "Показувати навантаження",
  "up": "працює {d} д {h} год",
  "things": { "one": "{n} річ", "few": "{n} речі", "many": "{n} речей", "other": "{n} речі" }
}
```

`t('key')` читає рядки віджета мовою людини (англійською, якщо ключа в її мові немає),
`t('up', { d: 3, h: 4 })` підставляє `{d}` і `{h}`, а ключ з `one`/`few`/`many`/`other` вибирає
форму множини для `{n}`. `title` — назва віджета в Налаштуваннях. Нова мова — новий файл,
`i18n/pl.json`; такий файл у твоїй теці (`/etc/pve-homelab/widgets/weather/i18n/pl.json`)
додає мову й вбудованому віджету. Блок `i18n: { en: {…} }` у самому модулі теж працює для
віджетів, написаних так, але файли мають перевагу.

У `ctx` є ще `app` (меню: `app.prefs()`, `app.api`, …) і `zone`. Усе, що приходить із даних,
екрануй через `ui.esc`. Коли `render` падає чи `source` не відповідає, віджет показує помилку з
кнопкою «Спробувати ще», а журнал помилок (*Налаштування → Про програму*) її записує.

**Встановлення на хост:** скопіюй файли в `/etc/pve-homelab` (та сама будова) або, як
адміністратор, *Налаштування → Панель → Мої віджети → Встановити віджети…*: код `<id>.js`, вигляд
`<id>.css` і рядки `<id>.en.json`, `<id>.uk.json` … або `.zip`: із теками віджетів
(`<id>/widget.js`, `<id>/widget.css`, `<id>/i18n/<мова>.json`), із текою, побудованою як
`/etc/pve-homelab` (`widgets/<id>/…`, `designs/widgets/<id>.css`), або з `widget.js` та `i18n/`
згори, і тоді віджет зветься як zip. `new_widget.py` друкує команду `zip`. Повторне встановлення
замінює код і рядки тих мов, що надіслані; решта мов лишається.

**Віджет — це код.** Він працює в меню з правами того, хто увійшов, а його файл віддається кожному,
хто може відкрити меню, як і вбудовані: секретів у ньому не тримай. Тому ставити віджети може лише
адміністратор, і варто ставити лише ті, що написав сам чи яким довіряєш.

## Обмеження

Файл дизайну — до 512 КБ тексту UTF-8; одне встановлення — до 50 дизайнів і 8 МБ. `widget.js`
віджета — до 256 КБ, файл мови — до 64 КБ.
Встановлювати й видаляти можна з `Sys.Modify` на `/` у Proxmox: дизайн змінює меню для всіх на
хості, а годинник — це код, що працює в меню.
